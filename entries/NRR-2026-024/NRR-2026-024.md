## 预注册锚点

本项目预注册判据（`CLAUDE.md`「PoC 决策表」+ `PLAN.md` §九）：
- **端到端加速比 ≥5×**（相对最佳免费替代，同数据同 mask 同语义，含 H2D 传输与归并）→ 目标线

- **未达 ≥5× 目标线 → 记负结果 NRR**（标签 `NRR-2026-024`）

## 原始假设 `hypothesis`

预注册（CLAUDE.md PoC 决策表：NRR 阈值 ≥5×、最低可接受 ≥2×）：在 RTX 4060 Laptop GPU（sm_89）上，fc 加速器（pybind11 + CUDA 绑定，binding 级含传输）于固定 `corpus_synth_v1`（T=1218 × N=5000 × F=12）最小参数扫描流水（parameter_scan → 逐因子 rolling_ic → factor_corr + IC 归并，verdict_scope 排除 stock_corr）相对最佳免费替代（qgplearn 未安装 → min(numpy 2.4.4, cupy 14.1.1)，同数据同 mask 同语义，含 H2D 传输与归并）端到端加速比 ≥5×。

## 方法 `method`

预注册锚点：CLAUDE.md PoC 决策表（≥5× NRR 阈值 / ≥2× 最低）与 PLAN.md §九。

**端到端（主判据）**：`benchmarks/poc4_e2e_v1.py` + `benchmarks/phase4_bench_v1.py`——最小参数扫描流水，GPU 臂 pybind11 绑定（`factor_cuda_pybind`/`factor_corr_pybind`），numpy/cupy 臂 `benchmarks/backends.py`，对称 reps + Phase 4 fresh 轮（**臂序轮转 + 热采样 + bootstrap CI**），`best_free=min(numpy,cupy)` 运行时记录，`verdict_scope` 排除 stock_corr。**判据统计量 = min-of-run-medians（最坏情况，跨 fresh 轮）**。

**单算子（产品层补充）**：`phase4_bench_v1.py` binding 级（含 H2D/D2H）vs numpy/cupy，median + bootstrap 95% CI + CV，warm 3 + 20 采样（原样持久化）；适配层开销单独测量（fc 适配器 vs 裸绑定）。

**复现性**：双 corpus 经 `corpus_loader_v1.py` 校验 data_sha256（fail-closed）；流水两 run 输出哈希逐位相等；G6 证据 self-hash 实门（源文件缺失/脏即 FAIL）；git HEAD 钉扎；corpus_real_v1（N=93）仅正确性 + 确定性锚点，不产 perf 数字。

## 预期结果 `expected_result`

假设成立：F=12 端到端加速比 ≥5×（相对 best-free，含传输与归并）；单算子 ≥2×。预注册失败判据：<2× → STOP；≥2× 且 <5× → 记负结果 NRR-2026-024。

## 实际结果 `actual_result`

**E2E F=12 端到端加速比 3.035–3.046×**（committed `poc4_e2e_v1.json` 3.0353×；Phase 4 fresh 轮 3.046×，臂序轮转后消除固定臂序热偏置；跨 run delta 0.34% 稳定）。≥2× 最低可接受达成（PASS-partial），**≥5× 预注册目标未达成（假设被证伪）**。

**单算子（binding 级含传输，corpus_synth_v1 全量，vs best-free）**：除 factor_corr 外全部 <5×；factor_corr ~12–15×（≥5×，binding 级）；cs_rank/parameter_scan/rolling_ic/stock_corr general 观察区间 1.6–3.8×。

> **⚠️ 跨会话方差披露**：本机（RTX 4060 Laptop）单算子中位数跨会话波动可达 ~2×（如 cs_rank 1.6×→3.1×、cupy 基线 69ms→218ms）。单算子边界断言（如 cs_rank <2×）**不跨会话稳定、仅作指示性**；E2E 判据（预注册决策）稳定。

**组件级负结果（显式暴露）**：e2e 分操作 `ic_stack`（IC 归并）~0.72× 劣于基线，不埋入聚合 ≥2× PASS。

**关键层差异**：早期验收 below_5x（cs_rank 3.01× / parameter_scan 3.02× / rolling_ic 3.14×）为 **kernel-resident**（GPU 纯计算、不含传输）口径；产品实际支付（binding 含传输）更低。适配层 factor_corr f32→f64 Python upcast 额外开销 +178%~+266%（**产品层 factor_corr ~3.98× <5×，binding 级 12–15×**）。

## 效果量 `effect_size`

E2E F=12 speedup 3.035–3.046×（预注册目标 5×，达成度 ~61%；≥2× 下限达成；判据统计量=min-of-run-medians）。factor_corr 12–15×（binding 级，≥5× 例外）；其余单算子 1.6–3.8×（跨会话波动，指示性）。

## 为什么失败 / 解读 `interpretation`

预注册 ≥5× 端到端目标未达成（3.04×），≥2× 最低可接受达成。归因**分机制、均标注为候选而非已证实**：

1. **FP64 硬件天花板**（候选机制，未做 FP32 聚合路径的确认实验）：RTX 4060 Laptop FP64 ≈ FP32/64 可能限制 float64 聚合操作（rolling_ic/factor_corr 一般归约/stock_corr general）的加速上限；但同证据集 **factor_corr（float64）达 12–15×**，削弱天花板为主因的强度。
2. **launch/传输/占用开销**（候选机制）：解释 float32 操作（cs_rank/parameter_scan）与产品层传输成本。
3. **阳性对照（binding 级）证明内核可达 ≥5×**：factor_corr 12–15×（同 corpus_synth_v1 非退化面板），below_5x 是负载/层相关而非普遍内核低效。
4. **kernel-resident 口径高估用户侧**：早期验收为 GPU 纯计算口径，产品实际支付（含传输）更低。
5. **适配层 Python 开销**：fc 适配器契约强制 f32→f64 Python upcast（factor_corr +178%~+266%），产品层 factor_corr ~3.98× <5×，为产品优化机会非绑定缺陷。

**跨会话方差**：单算子中位数在本机跨会话波动 ~2×，故单算子边界断言不作决策依据，决策仅依 E2E（稳定）。未验证的替代解释（更高 FP64 吞吐 GPU、FP32 聚合路径、kernel 调优）标为**未验证假设**。结论限定于 RTX 4060 Laptop + 固定 corpus + 排除 stock_corr 的 E2E 口径，不推广至其他 GPU 或 FP64 不占主导的工作负载。

## 可复现性 `reproducibility`

- **level**: `partially-reproducible`（同机同 commit 同 corpus → 输出位级确定性；计时跨会话/异机不可搬移）
- **artifacts_available**: code, data, logs, analysis-script, raw-output
- **notes**: corpus manifest 已提交（real data_sha256=FB23D9E1…8504F；synth 由 loader 运行时确认）；流水输出两 run 哈希逐位相等；G6 证据 self-hash 实门（11 源文件，0 mismatch）；git HEAD 钉扎。qgplearn 基线臂未安装，best-free=min(numpy,cupy) 为替代，故 level 为 partially-reproducible（非 fully）。本机单算子跨会话波动 ~2× 已披露。

## 相关阳性结果 `related_positive_result`

同证据集阳性对照（binding 级）：corpus_synth_v1 全量（非退化面板、同 corpus）上 factor_corr 12–15×（≥5× PASS）证明同一批内核可达 ≥5×，把 below_5x 隔离为负载/层相关而非普遍低效；但产品适配层 factor_corr ~3.98×（Python upcast 开销），**阳性对照须限定 binding 级**。stock_corr fast 路径（全有效退化-mask 合成面板特例）5–12× 须与 general 口径并排，不单独用作内核能力证据。

## 教训 `lessons_learned`

1. **预注册双阈值（≥2× 最低 / ≥5× 目标）使 3.04× 成为无歧义裁决**：下限达成、目标未达 → 如实记负，不得把已记录缺口包装为成功。
2. **消费级 GPU（RTX 40 系）性能方差大**——单算子加速比跨会话可波动 ~2×（cs_rank 1.6×→3.1×），预注册决策须基于稳健的端到端判据而非波动大的单算子边界。
3. **性能声明必须标注层与传输口径**：kernel-resident（GPU 纯计算）、binding 含传输（用户支付）、适配层（产品）三层可差 2–3×；同一操作不同口径给出不同边界结论。
4. **『≥5× 可达』须分机制锚定**：binding 级 factor_corr 12–15× 证明内核可超 5×，但产品适配层 f32→f64 Python upcast 开销把产品层降至 ~3.98×——产品层与内核层分别报告。
5. **E2E 判定口径运行前声明并沿用**（verdict_scope 排除 stock_corr）；组件级负结果（ic_stack 0.72×）显式暴露，不埋入聚合 PASS；benchmark 须臂序轮转 + 热采样防固定臂序偏置。
