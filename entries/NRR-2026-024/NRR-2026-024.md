## 预注册锚点

本项目预注册判据（`CLAUDE.md`「PoC 决策表」+ `PLAN.md` §九）：
- **端到端加速比 ≥5×**（相对最佳免费替代，同数据同 mask 同语义，含 H2D 传输与归并）→ 目标线
- **≥2×** → 最低可接受（PASS）
- **<2×** → STOP（负结果）
- **未达 ≥5× 目标线 → 记负结果 NRR**（标签 `NRR-2026-024`）

## 原始假设 `hypothesis`

在 RTX 4060 Laptop GPU（sm_89）上，fc 适配器（pybind11 + CUDA）于固定 `corpus_synth_v1`（T=1218 × N=5000 × F=12）最小参数扫描流水（parameter_scan → 逐因子 rolling_ic → factor_corr + IC 归并，verdict_scope 排除 stock_corr）相对最佳免费替代（qgplearn 未安装 → min(numpy 2.4.4, cupy 14.1.1)，同数据同 mask 同语义，含 H2D 传输与归并）**端到端加速比 ≥5×**。

## 方法 `method`

预注册锚点：`CLAUDE.md` PoC 决策表（≥5× NRR 阈值 / ≥2× 最低）与 `PLAN.md` §九一致。

**端到端（主判据）**：`benchmarks/poc4_e2e_v1.py`——F∈{4,8,12} 最小参数扫描流水，GPU 臂用 pybind11 绑定（`factor_cuda_pybind`/`factor_corr_pybind`），numpy/cupy 臂用 `benchmarks/backends.py`，对称 reps，`verdict_scope` 明确排除 stock_corr。`best_free=min(numpy,cupy)`（qgplearn 未安装，运行时记录获胜免费臂）。Phase 4 重新执行 fresh 轮 + 跨 run 稳定性门。

**单算子（产品层）**：`benchmarks/phase4_bench_v1.py`——binding 级（含 H2D 传输 + D2H，与 e2e 同层）vs numpy/cupy 最佳免费替代，median + bootstrap 95% CI（1000 resamples, seed=0）+ CV，warm 3 + 20 采样，逐块 nvidia-smi 热采样。corpus_synth_v1 全量。

**复现性**：双 corpus（synth + real）经 `corpus_loader_v1.py` 校验 data_sha256（fail-closed）；流水两 run 输出哈希逐位相等；git HEAD 钉扎 + 证据文件 self-hash；corpus_real_v1（N=93）仅作正确性 + 确定性锚点，不产 perf 数字。

## 预期结果 `expected_result`

假设成立：F=12 端到端加速比 ≥5×（相对 best-free，含传输与归并）；单算子 ≥2×；float64 聚合类（rolling_ic/factor_corr）预期贡献主要加速。预注册失败判据：<2× → STOP；≥2× 且 <5× → 记负结果 NRR-2026-024。

## 实际结果 `actual_result`

**E2E F=12 端到端加速比 ~3.03–3.04×**（committed `poc4_e2e_v1.json` 记录 3.0353×；Phase 2-3 验收 fresh 3.03×；Phase 4 fresh 轮见证据文件）。≥2× 最低可接受达成（PASS），**≥5× 预注册目标未达成**。

**单算子（binding 级，含传输，corpus_synth_v1 全量）**：

| 操作 | 加速比 vs best-free | 判定 |
|---|---|---|
| cs_rank | ~1.8× | **<2× 产品层下限** |
| parameter_scan(G=4) | ~2.3× | ≥2× 但 <5× |
| rolling_ic | ~2.0× | ≥2× 但 <5× |
| factor_corr | ~13× | **≥5× PASS** |
| stock_corr general(N=500) | ~3.3× | ≥2× 但 <5× |
| stock_corr general(N=2000) | ~2.5× | ≥2× 但 <5× |

**组件级负结果（显式暴露）**：e2e 分操作中 `ic_stack`（IC 归并，单次 (4F,T) np.stack）加速比 ~0.72×，**劣于基线**——小操作 Python/numpy 固定开销主导，不埋入聚合 ≥2× PASS。

**关键层差异发现**：本项目早期验收的 below_5x（cs_rank 3.01× / parameter_scan 3.02× / rolling_ic 3.14×）为 **kernel-resident**（GPU 纯计算、不含传输）口径；**产品实际支付（binding 含传输）更低**，cs_rank 甚至低于 2×。kernel-resident 口径高估用户侧加速比。

## 效果量 `effect_size`

E2E F=12 speedup ≈ 3.03×（预注册目标 5×，达成度 ~60%，缺口 ~2×；≥2× 下限达成）。单算子产品层区间 1.8–13.2×（6 项，各带 corpus/panel 溯源）。阳性对照：factor_corr ~13×（≥5×，同 corpus_synth_v1 非退化面板）。

## 样本 `sample_size`

corpus_synth_v1：T=1218 × N=5000 × F=12。单算子 warm 3 + 20 采样 + bootstrap CI(1000)；e2e F∈{4,8,12} 对称 reps + Phase 4 fresh 轮。corpus_real_v1：T=1212 × N=93 × F=3（仅正确性/确定性）。qgplearn 未安装 → 该基线臂缺失，best-free=min(numpy,cupy)。

## 涉及模型/工具 `models_used`

DeepSeek-V4-Flash (via Claude Code CLI)；CUDA 13.3；pybind11；numpy 2.4.4；cupy 14.1.1；RTX 4060 Laptop GPU。

## 为什么失败 / 解读 `interpretation`

预注册 ≥5× 端到端目标未达成（~3.03×），≥2× 最低可接受达成。归因**分机制**、不作单一概括：

1. **FP64 硬件天花板**（主因，仅解释 float64 聚合操作）：RTX 4060 Laptop FP64 吞吐 ≈ FP32 的 1/64（官方架构特性，物理上限）。rolling_ic（~2.0×）、stock_corr general（~2.5–3.3×）与 factor_corr 的一般归约均受限。
2. **launch/传输/占用开销**（解释 float32 操作 + 产品层缺口）：cs_rank（~1.8×）、parameter_scan（~2.3×）的 <2× 缺口不可归因 FP64，机制为 per-call H2D/D2H 传输 + kernel launch + 小面板占用。
3. **阳性对照证明非普遍低效**：同证据集、同 corpus_synth_v1 非退化面板上 factor_corr ~13×（≥5× PASS）——同一批内核可达 ≥5×，below_5x 是**负载相关**而非普遍内核低效。
4. **kernel-resident 口径高估用户侧**：早期验收的 below_5x 为 GPU 纯计算口径（无传输）；产品实际支付（binding 含传输）更低。这是报告口径的方法论教训——性能声明必须标注传输口径。
5. **适配层 Python 开销**：fc 适配器对 factor_corr 的契约强制 f32→f64 Python astype（~1s/调用，相对绑定内部 forcecast upcast 慢 ~266%）——产品 Python 层有可优化空间，非绑定缺陷。

未验证的替代解释（更高 FP64 吞吐 GPU、FP32 聚合路径、kernel 调优）标为**未验证假设**而非可行性声明。结论限定于 RTX 4060 Laptop + 固定 corpus + 排除 stock_corr 的 E2E 口径，不推广至其他 GPU 或 FP64 不占主导的工作负载。

## 相关阳性结果 `related_positive_result`

同证据集阳性对照（不掩盖缺口）：corpus_synth_v1 全量（非退化面板、同 corpus）上 factor_corr ~13×（≥5× PASS）证明同一批内核可达 ≥5×，把 below_5x 隔离为负载/硬件相关而非普遍低效。stock_corr fast 路径（全有效退化-mask 合成面板特例）5–12× 须与 general 口径并排，不单独用作内核能力证据。

## 教训 `lessons_learned`

1. **预注册双阈值（≥2× 最低 / ≥5× 目标）使 ~3.03× 成为无歧义裁决**：下限达成、目标未达 → 如实记负，不得把已记录缺口包装为成功。
2. **消费级 GPU（RTX 40 系）FP64 ≈ FP32/64 是 float64 聚合工作负载的硬天花板**——设 ≥5× 目标前先查设备 FP64 规格，或为聚合内核设计 FP32 路径。
3. **性能声明必须标注传输口径**：kernel-resident（GPU 纯计算）与 binding-含传输（用户实际支付）可差 2–3×（cs_rank 3.01× vs 1.8×）——"加速比"未标注口径即误导。
4. **硬件天花板归因须分机制 + 同证据集阳性对照锚定**：FP64 天花板只解释 float64 操作；float32 的 <2× 归因 launch/传输/占用；factor_corr ~13× 证明内核可超 5×。
5. **E2E 判定口径运行前声明并沿用**（verdict_scope 排除 stock_corr）；组件级负结果（ic_stack 0.72×）显式暴露，不埋入聚合 PASS。
