## Experiment Overview

### Original Hypothesis

> The CALLS edges in the GitNexus code knowledge graph should reliably capture method-call relationships, including calls within the same file. Expected index coverage was ≥80%, making the edges suitable for asserting module-internal coupling.

### Method

Manual source-code grep cross-validation was performed on two core modules in the docx-pipeline project: PurePythonConverter (1,213 lines, 36 methods) and MermaidRenderer (677 lines, 17 methods). The number of CALLS edges in the GitNexus index was compared with the actual call chains in the source.

### Expected Result

> GitNexus CALLS edges should cover ≥80% of same-file internal calls.

### Actual Result

PurePythonConverter: only **3** same-file CALLS edges were captured (coverage ≤3.7%). MermaidRenderer: **0** same-file CALLS edges were captured (0% coverage). Asserting module-internal coupling from GitNexus CALLS edges is unreliable.

## Interpretation and Reflection

### Why Did It Fail?

The indexing strategy for same-file CALLS edges has different detection accuracy from cross-file calls. This is not a bug but a difference in indexing precision across dimensions. However, for methodology extraction, blindly trusting index data would systematically underestimate module complexity.

### What Did We Learn?

1. Same-file coverage of GitNexus CALLS edges can be as low as 0%—do not assert module-internal coupling from CALLS-edge counts
2. AI-tool evaluation cannot rely only on static source analysis—controlled experiments are needed to reveal blind spots
3. Cross-file IMPORT/EXTENDS edges are more reliable than same-file CALLS edges
4. Claims made by any analysis tool require cross-validation—“3 CALLS edges” may be only 3.7% of the truth
