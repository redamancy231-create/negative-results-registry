## Experiment Overview

### Original Hypothesis

> The methodology-extraction framework should be able to extract meaningful methodology patterns from unknown open-source projects—even when a project has no AI collaboration records, usable signals should be extractable from passive traces. The expected minimum gradient (a pure-code project) had an extraction rate of ≥50%.

### Method

A complete eight-component extraction was performed across three project gradients: own projects (★★★★★), ml-quant-trading (★★★, with paper + CI + tests), and NPGS (★, with zero methodology documentation).

### Expected Result

> Extraction rates should decline progressively across the three gradients while retaining a baseline—NPGS ≥50% (4/8).

### Actual Result

**The gradient was 100% → 69% → 37.5%.** Five of eight NPGS components were blank. The three extractable components could also be obtained with GitNexus, meaning the framework had **no incremental value** for passive traces.

## Interpretation and Reflection

### Why Did It Fail?

The framework's implicit assumption—“the source project knows what it did and recorded it”—does not hold for most open-source projects. The framework is not a “detector” but an “organizer”: it cannot discover information that does not exist.

### What Did We Learn?

1. The framework's applicable population is extremely narrow—it works only for projects with very strong AI-collaboration self-awareness
2. Extraction rate is positively associated with the source project's methodological self-awareness (★★★★★=100%→★=37.5%)
3. The framework has no incremental value for passive traces—anything GitNexus can obtain does not require the framework
4. The framework's value proposition should be corrected from “discovery” to “synthesis”—it is not a detector but an organizer
