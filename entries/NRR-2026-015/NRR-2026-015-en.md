## Experiment Overview

### Original Hypothesis

> After release cleanup was complete, scanning with the project's own grep pattern could confirm “zero residue.”

### Method

Framework release preparation: three rounds of cleanup + self-check claimed zero residue → three rounds of independent Codex scans by a different backend found new residue each time.

### Expected Result

> Zero residue should be achieved after the first cleanup + self-check.

### Actual Result

**The “zero residue” claim was made three times and disproven three times (100% false-positive rate):** (1) absolute paths/usernames remained → (2) four-layer path variants remained → (3) residue remained in files excluded by `.gitignore`. Root cause: the same brain using the same grep pattern 10 times produced the same blind spot ×10.

| Metric | Value |
|------|------|
| Effect size | All 3/3 “zero residue” claims were disproven (100% false-positive rate) |
| Sample size | 3 cleanup + self-check rounds × 3 independent Codex scan rounds |
| Models used | DeepSeek-V4-Pro, GPT-5.5 |

---

## Interpretation and Reflection

It is unreliable for the cleaner to declare “zero residue” personally—the brain has already formed the cognition that the item was “handled” during editing, and grep merely confirms that cognition. Independent scans by a different backend use different search strategies and naturally hit the operator's blind spots.

### What Did We Learn?

1. The same brain using the same grep pattern 10 times = the same blind spot ×10
2. A cleaner's self-declaration of “zero residue” is unreliable—a cognitive-bias problem
3. Independent scanning by a different backend is necessary: different search strategies provide different blind-spot coverage
4. Path cleanup has four layers of variants—a single grep cannot exhaust them all
