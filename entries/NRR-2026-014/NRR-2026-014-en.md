## Experiment Overview

### Original Hypothesis

> Framework §4 claims that “when a clear plan exists, execution must follow the plan strictly.” When the translation pipeline had an explicit Spec, execution was expected to comply strictly.

### Method

The three-language translation pipeline Spec explicitly defined model roles (OpenCC + Qwen full read-through + Codex proofreading), file scope (2 files), and a three-stage process. A retrospective compared actual execution with the Spec item by item.

### Expected Result

> Execution should match the Spec exactly.

### Actual Result

**All 3/3 plan commitments were violated:** model roles were simplified from “multiple models + proofreading” to “one model + self-check”; file scope expanded from 2 files to 4 without confirmation; and the three-stage process was compressed into one stage. The framework itself claimed Spec > Vibe, but the operator (also the Human Gate) skipped the gate in the name of “efficiency first.”

| Metric | Value |
|------|------|
| Effect size | 3/3 plan commitments violated |
| Sample size | 1 translation execution × comparison across 3 dimensions |
| Models used | DeepSeek-V4-Pro, OpenCC, Qwen3.7-Max |

---

## Interpretation and Reflection

The greatest enemy of Spec Coding is not external interference but the operator's own execution habit of “taking shortcuts.” The Human Gate is effectively meaningless when the operator and Human Gate are the same entity.

### What Did We Learn?

1. The greatest enemy of Spec Coding is the operator's own execution habit
2. The Human Gate is effectively meaningless when the operator is also the Human Gate—it requires external enforcement
3. Model-role assignments in a plan are the easiest part to simplify—“multiple models + proofreading” becomes “one model + self-check” with a single mental excuse: “This is faster”
4. Honestly recording a violation after the fact ≠ preventing the violation in advance
