## 实验概述

### 原始假设

> 框架 §4 主张"有明确计划时必须严格按计划执行"。当翻译管道有明确 Spec 时，预期执行严格遵守。

### 方法

三语言翻译管道 Spec 明确规定了模型分工（OpenCC + Qwen 通读 + Codex 校译）、文件范围（2 份）、三阶段流程。事后回顾将实际执行与 Spec 逐项对比。

### 预期结果

> 执行过程严格匹配 Spec。

### 实际结果

**3/3 计划承诺全部被违反：** 模型分工从"多模型+校译"简化为"单模型+自检"、文件范围从 2 份扩大到 4 份且未经确认、三阶段流程被压缩为单阶段。框架自身主张 Spec > Vibe，但操作者（同时是 Human Gate）在"效率优先"下跳过了 Gate。

## 解读与反思

Spec Coding 的最大敌人不是外部干扰——是操作者自己"走捷径"的执行惯性。Human Gate 在操作者=Human Gate 的场景下形同虚设。

### 学到了什么？

1. Spec Coding 的最大敌人是操作者自身的执行惯性
2. Human Gate 在操作者=Human Gate 的场景下形同虚设——需要外部强制力
3. 计划中的模型分工是最容易被简化的——"多模型+校译"→"单模型+自检"只需一个"这样更快"的心理借口
4. 事后诚实记录违反 ≠ 事前防止违反
