## 实验概述

### 原始假设

> 在对 fork 的源项目进行方法论提取时，fork 仓库中所有文件应反映源项目的方法论特征。预期附加文档能补充源项目的方法论信息。

### 方法

对 NPGS（baopinshui/NPGS）进行完整方法论提取。该仓库被 fork 后，提取者添加了 CLAUDE.md、GitNexus 索引和分析报告，然后从 fork 仓库执行提取。事后追溯哪些文档来自源作者、哪些来自提取者。

### 预期结果

> 至少部分附加文档应反映或补充源项目的方法论特征。

### 实际结果

**CLAUDE.md、GitNexus 索引、分析报告 100% 来自 fork 提取者。** 源项目方法论文档=0。如果不区分两者，提取者会把"自己编写的唯一方法论文档"误归因为"源项目有方法论自觉"。

## 解读与反思

### 为什么会失败？

提取框架的 Phase 0 设计缺陷。当提取者也是仓库中唯一方法论文档的作者时，默认假设"仓库文档反映源项目"会系统性高估源项目的方法论自觉。

### 学到了什么？

1. 提取者的文档≠源项目的方法论——制造虚假信号
2. Phase 0 需要"提取者污染"判别——检查文档作者 ≠ 源项目作者时降权
3. fork 后添加的分析工件不应被当作源项目方法论——观察者效应
4. 源项目文档=0 是诚实信号，不是提取失败
