## Experiment Overview

### Original Hypothesis

> After accelerating the pure-compute core of a pattern-matching ETF strategy with pybind11 + C++20, batch workloads were expected to achieve end-to-end speedups close to those of individual calls (expected: 10–30×).

### Method

The pure-compute Python core (DTW, pattern matching, and technical indicators) was migrated to C++ and exposed through pybind11. Measurements compared (a) individual Python versus C++ calls, (b) Python versus C++ batch processing at 100 time points, and (c) 100 individual C++ calls versus one C++ batch call. Pure-compute modules were extracted from V3.3.py (3,836 lines), excluding functions dependent on sklearn/scipy/pandas.

### Expected Result

> Individual DTW calls ≥10×, individual pattern-matching calls ≥30×, and batch end-to-end performance ≥10×.

### Actual Result

Individual DTW calls achieved 34× and individual pattern-matching calls achieved 53×, both exceeding expectations. However, **batch end-to-end performance improved by only 2.2×**—far below the per-call speedup. Root cause: only **~56% of the batch workload was accelerable** (p≈0.556), while 44% was serial overhead. The theoretical speedup ceiling was 1/(1-p)≈2.25×; the measured 2.2× was already near that ceiling.

| Metric | Value |
|------|------|
| Effect size | Individual call 53× → batch 2.2× (24× attenuation); theoretical ceiling ≈2.25× |
| Sample size | 100 warm-up runs + median of 100 timed runs × 6 functions |
| Serial fraction | 44% (Python loops 15% + data conversion 15% + pybind11 calls 8% + feature computation 6%) |
| Models used | DeepSeek-V4-Pro, Kimi-K2.7-Code |

## Interpretation and Reflection

### Why Did It Fail?

**This is a textbook example of Amdahl's Law.** The 53× per-call speedup was not “wrong”—both 53× and 2.2× were accurate measurements of different things. The 53× figure measured the pure-compute hot path (14.0 ms→0.26 ms); 2.2× measured end-to-end batch throughput (50 ms→23 ms, including non-accelerable orchestration, data movement, and Python/C++ boundary overhead). This was not a bug; it was an architectural ceiling.

### What Did We Learn?

1. **Amdahl's Law is not a theoretical abstraction**—the measured 2.2× versus a 2.25× ceiling shows that mathematical modeling closely matched real measurements in a quantitative-computing workload
2. **“Per-call speedup” and “end-to-end speedup” are entirely different metrics**—the former describes computational efficiency; the latter describes throughput improvement visible to the user
3. **The 44% serial overhead was decomposed precisely into four categories** (loops/conversion/calls/features), each requiring a different optimization strategy
4. **Achieving 10× end-to-end requires 92% of the workload to be accelerable**—architectural restructuring may be more fundamental than further C++ migration
