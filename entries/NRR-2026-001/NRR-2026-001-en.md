## Experiment Overview

### Original Hypothesis

> Structuring a code-review prompt into three stages—prep (loading specifications), exec (reviewing files one by one), and post (cross-checking)—was expected to improve the quality of GPT-5.5 findings in multi-file code review relative to a single-block baseline prompt that reviewed all specifications and all files together.

### Method

Prompt-TDD controlled experiment design:
- **Experimental group**: three-stage prep/exec/post prompt (A2 variant)
- **Control group**: single-block comprehensive prompt (A2 baseline)
- **Task**: review the same codebase across multiple files and record the number of findings, severity, and false-positive rate
- **Sample size**: n=24/arm
- **Cross-model replication**: primary experiment with GPT-5.5 plus independent replication with Qwen3.7-Max
- **Evaluation**: blinded evaluation by two LLMs using separate backends (reviewers did not know which group was experimental)

### Expected Result

> The three-stage prompt should produce more high-quality findings and fewer false positives. Expected effect size: d ≥ 0.3 (small to medium).

### Actual Result

The two groups showed no significant differences in the number of findings, severity distribution, or false-positive rate.

| Metric | Value |
|------|------|
| Effect size | d ≈ 0.03 (trivial) |
| Sample size | n=24/arm × replication with 2 models |
| Models used | GPT-5.5, Qwen3.7-Max |
| Replication consistency | Qwen replication Δ = −0.014, directionally consistent (both null) |

## Interpretation and Reflection

### Why Did It Fail?

The most likely explanation is that **the task type determines the upper bound on the effect size of prompt variations**. Code review is a structured classification task: the reviewer checks explicit specifications item by item. In such tasks, prompt “packaging” (segmented versus single-block) has much less influence on output quality than the constraints imposed by the task itself. Put differently, when the specifications are sufficiently explicit, how the prompt is written matters much less.

### What Did We Learn?

1. **Prompt-variation effects are near zero on structured classification tasks**—unlike open-ended generation tasks such as translation and writing, where prompt variations have larger effects
2. **The specification itself matters more than prompt structure**—invest effort in writing strong review criteria rather than organizing prompt paragraphs
3. **Negative results require cross-model replication**—the null effect with GPT-5.5 could have been single-model noise; the Qwen replication confirmed that the effect was indeed null
4. **Separating the experiment's “engineering gate” from its “scientific gate” is valuable**—even with a negative result, the experimental structure itself remains reusable
5. **Effect sizes should be estimated with a ceiling probe before the experiment**—had the ceiling effect for structured classification been known, expectations for this direction would likely have been lower
